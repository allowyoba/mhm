# mhm 0.1.1

Расширение для профилей и подписок mihomo. Поддерживает Chrome, Edge, Firefox и Opera на Windows, macOS и Linux. Интерфейс доступен на русском, английском и китайском языках.

## Установка

Установите пакет расширения для своего браузера. Для локальной проверки Chrome, Edge и Opera загрузите распакованный каталог в режиме разработчика через `chrome://extensions`, `edge://extensions` или `opera://extensions`. Firefox XPI можно временно загрузить через `about:debugging`. Постоянная установка Firefox требует подписи Mozilla.

Откройте mhm. Первый запуск показывает проверку компонентов и команду для вашей ОС, архитектуры и ID расширения.

### Windows и macOS

Запустите установщик из папки со скачанным файлом. Для macOS Apple silicon выполните следующие команды.

```sh
chmod +x ./mhm-setup-0.1.1-macos-arm64
./mhm-setup-0.1.1-macos-arm64 install --browser chrome --extension-id YOUR_EXTENSION_ID
```

Для Windows выполните команду из PowerShell.

```powershell
.\mhm-setup-0.1.1-windows-amd64.exe install --browser edge --extension-id YOUR_EXTENSION_ID
```

Установщик включает Python и native host, загружает официальный стабильный mihomo и проверяет SHA-256. Существующий бинарник можно передать через `--mihomo PATH`. Для Firefox используется `--browser firefox --extension-id mhm@allowyoba.github.io`.

### Linux через deb / apt

Локальная сборка проверяется на Debian 12. Пакет рассчитан на Debian 12+ и совместимые Ubuntu с glibc 2.36+, включая Ubuntu 24.04. Доступны сборки amd64 и arm64.

```sh
sudo apt install ./mhm_0.1.1_amd64.deb
mhm-setup install --browser edge --extension-id YOUR_EXTENSION_ID
```

APT устанавливает зависимости. В пакете находятся native host, mihomo и команда `mhm-setup`. Регистрацию браузера выполняйте от обычного пользователя рабочего стола. ID можно взять со страницы первого запуска, либо установщик обнаружит уже установленное расширение автоматически.

Профили шифруются ключом из Secret Service. Нужен запущенный и разблокированный GNOME Keyring либо совместимое хранилище, предоставляющее `org.freedesktop.secrets`. Команда `secret-tool` устанавливается зависимостью пакета. При недоступном хранилище mhm предложит его разблокировать. Хранение новых секретов открытым текстом исключено. Старые приватные файлы секретов мигрируют в шифрованное хранилище после успешного доступа к keyring.

После установки нажмите «Проверить снова», добавьте подписку или YAML-профиль, затем подключитесь.

## Использование

Раздел «Подключение» содержит выбор профиля, включение прокси, режим маршрутизации, группы и проверку задержки. Ручные группы позволяют выбрать узел, автоматические показывают результат выбора движка. Задержка измеряется через mihomo и отображается в миллисекундах.

В разделе «Профили» находятся поиск, добавление, редактирование и обновление. Полный YAML сохраняет группы, правила, DNS и providers. Подписка только с узлами получает группу выбора и завершающее правило. Обновления доступны вручную и каждые 6, 12 либо 24 часа, пока браузер работает.

Новая версия проходит проверку до сохранения. Активное соединение использует свою ревизию до нажатия «Применить». При ошибке загрузки остаётся рабочая конфигурация. Доступен откат предыдущей версии.

Иконка показывает состояние подключения. Зелёный индикатор означает подключение, анимация — подключение в процессе, красный — обрыв с блокировкой либо исчерпанный лимит. Подсказка содержит статус и имя профиля. Значок `!` предупреждает о расходе бюджета.

### Трафик и лимиты

Раздел «Трафик» показывает загрузку и отправку за сегодня, календарный месяц и всё время, график за 30 дней и последние подключения. Данные сохраняются локально в SQLite и переживают перезапуск браузера.

Локальный лимит учитывает сумму загрузки и отправки всех профилей на этом компьютере. Доступны дневной период и месячный цикл с выбранным днём обновления. Если дня нет в текущем месяце, используется последний день месяца.

На 80% бюджета появляется предупреждение. При исчерпании можно оставить предупреждение либо остановить прокси. Остановка выполняется native host даже при закрытом popup. Новое подключение блокируется до обновления периода, увеличения или отключения лимита. Кнопка «Отключить» возвращает обычное соединение браузера. Показатели счётчика обновляются с небольшой задержкой.

Квота провайдера из заголовка подписки отображается отдельно в профиле и обновляется при загрузке подписки.

### Пользовательские правила

Выберите профиль в разделе «Правила». Конструктор поддерживает точный домен, домен с поддоменами, ключевое слово, IPv4/IPv6-сеть и весь трафик. Целью может быть DIRECT, REJECT или группа профиля. Правила можно переставлять, удалять и редактировать текстом в формате mihomo.

Пользовательские правила применяются перед исходными правилами и сохраняются при обновлении подписки. Кнопка «Проверить и сохранить» проверяет всю результирующую конфигурацию. Изменения начинают действовать при следующем подключении или после применения к активному профилю.

### WireGuard и HTTPS

В подписке можно выбрать загрузку через временный WireGuard-туннель. Импортируйте `.conf` с одним Interface и одним Peer. Поддерживаются частичные AllowedIPs, IPv4/IPv6, DNS, MTU, PresharedKey и PersistentKeepalive. Адрес подписки и внутренний DNS должны быть доступны через указанные маршруты. Туннель закрывается после загрузки. При ошибке обходной загрузки напрямую не происходит.

Для HTTPS доступны системное доверие, собственный CA в PEM/DER и игнорирование ошибок сертификата. Собственный CA и настройка сохраняются с зашифрованным профилем. Игнорирование отключает проверку сертификата и имени сервера, отмечается предупреждением. Эти настройки действуют для исходного сервера подписки. При перенаправлении на другой сервер применяется системная проверка.

## Защищённое хранение

На Windows используется DPAPI текущего пользователя. На macOS и Linux профили шифруются AES-256-GCM, ключ хранится в Keychain или Secret Service. Секреты передаются системному хранилищу через API либо stdin, без значений в аргументах процессов.

Исходный YAML, URL подписок, HTTP-заголовки и ключи WireGuard исключены из browser storage. Runtime-конфигурация находится в приватном временном каталоге, удаляется после загрузки движком. Кеш providers шифруется при остановке. Watchdog завершает дочерние процессы и очищает runtime-каталог при аварийном завершении host.

Native Messaging использует имя `io.mhm.browser`, Firefox — ID `mhm@allowyoba.github.io`. Браузерные DNS, DoH, WebRTC и QUIC требуют проверки в вашей конфигурации.

mhm управляет браузерным прокси и локальными портами движка. TUN, LAN и дополнительные listeners отключаются. Providers поддерживаются через HTTPS и inline. Файловые providers требуют самодостаточной конфигурации. Ключи и сертификаты следует встраивать в YAML.

## Обслуживание

```sh
mhm-setup diagnose --json
mhm-setup repair
mhm-setup uninstall
```

На Windows и macOS используйте соответствующий файл установщика вместо `mhm-setup`. Удаление пользовательской интеграции сохраняет профили и статистику. `uninstall --remove-user-data` удаляет их вместе с ключом шифрования.

На Linux сам системный пакет удаляется через `sudo apt remove mhm`. Пользовательские данные принадлежат пользователю рабочего стола. Для удаления данных сначала выполните `mhm-setup uninstall --remove-user-data` от этого пользователя.

## Разработка

Для сборки нужен Python 3.12+. JavaScript использует ES modules для UI и отдельные classic-скрипты для фонового процесса Firefox/Chromium. Исходные файлы версии и идентификаторов генерируются из `product.json`.

```sh
make setup
make version
make test
make lint
make build
make extensions
make smoke SMOKE_ARGS='--mihomo /path/to/mihomo'
make linux
```

`make linux` передаёт выбранные исходники в одноразовый Docker-контейнер, собирает пакет, устанавливает его через APT и проверяет Secret Service, четыре браузерные регистрации, правила, лимиты и реальный mihomo. Результаты находятся в `.build/linux-output`. Архитектура выбирается по Docker daemon, её можно задать через `MHM_LINUX_ARCH=amd64` или `arm64` при наличии подходящего runner/emulation.

Native runtime разделён на конфигурацию, профили, шифрование, сетевой транспорт, TLS, статистику, политики и платформенные примитивы. Native Messaging служит границей приложения. UI разделён на API, форматирование, трафик и правила; фоновые адаптеры отвечают за Native Messaging, прокси и иконку.

### APT-репозиторий

Создайте метаданные из собранных пакетов на Linux. Для публичного репозитория укажите существующий ключ GPG.

```sh
python scripts/build_apt_repository.py dist/mhm_0.1.1_amd64.deb --output dist/apt --signing-key YOUR_GPG_KEY_ID
```

Команда создаёт `Packages`, `Release`, `InRelease`, `Release.gpg` и экспорт публичного ключа. Разместите содержимое на своём HTTPS-сервере и подключите источник APT с `signed-by`, указывающим на экспортированный ключ. Без `--signing-key` создаются локальные неподписанные метаданные для проверки. Установка локального `.deb` через `apt install ./file.deb` не требует собственного репозитория.

CI в `.github/workflows/build.yml` собирает Windows, macOS и Linux amd64/arm64. Публикация магазинов, подпись Firefox XPI и нотарификация macOS выполняются перед публичным распространением.

## Релизы и CI

Готовые пакеты: https://github.com/allowyoba/mhm/releases. Правила внесения изменений находятся в [docs/contributing.md](contributing.md), обработка данных описана в [docs/privacy.md](privacy.md).

CI проверяет код и установку на Windows amd64, macOS arm64/amd64 и Linux amd64/arm64. Отдельная задача собирает пакеты четырёх браузеров и запускает Mozilla `web-ext lint`. Тег `X.Y.Z` должен совпадать с версией в `product.json`; после успешных задач CI публикует GitHub Release и `SHA256SUMS`.

Firefox отправляется в публичный каталог отдельным workflow `Submit Firefox to Mozilla`. Нужны секреты репозитория `AMO_JWT_ISSUER` и `AMO_JWT_SECRET` из кабинета Mozilla. Первичная регистрация выполняется командой `python3 scripts/sign_firefox.py --env-file .env`. Повторную отправку той же версии выполнять не нужно. Решение о публикации и срок проверки определяет Mozilla; успешная загрузка ещё не означает одобрение. Обычный Firefox XPI в GitHub Release остаётся неподписанным, пока подписанный файл не добавлен отдельно.

Подпись Windows и нотарификация macOS в CI не настроены. Публикация GitHub Release не размещает APT-сервис: архив репозитория можно развернуть отдельно и подписать собственным GPG-ключом.
