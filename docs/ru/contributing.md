# Изменения в mhm

Используйте ветки `feat/<name>`, `fix/<name>`, `ci/<name>` и другие типы Conventional Commits. Название должно кратко описывать изменение на английском, в нижнем регистре.

Коммит содержит одну строку без тела и trailers, например `fix: keep proxy blocked after a traffic limit`. Заголовок PR оформляется так же, описание остаётся пустым. По возможности укладывайтесь в 72 символа. Не добавляйте сведения об инструментах или авторстве генерации.

Комментарии объясняют только неочевидные ограничения: коротко, на простом английском, в нижнем регистре, без точки в конце. Регистр точных имён параметров и команд сохраняется.

Основную документацию пишите на английском; русские инструкции храните отдельно в `docs/`. Оставляйте назначение, команды, параметры и реальные ограничения. Проверяйте примеры по текущему коду.

Перед отправкой выполните `make lint test`. Изменения упаковки проверяйте сборкой и установкой на соответствующей ОС. Локальная проверка не заменяет CI для остальных платформ.
